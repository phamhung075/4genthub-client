# Architect ecosystem review (lead + architect)

The loop's periodic look outward: not one report, but the pattern across reports.

## Cadence

Per batch first; daily only if the trial earns it. A review that does not change a decision is not held again.

## Inputs (all existing surfaces)

- the feedback channel, grouped by `layer`;
- the board's `friction` items and their triage outcomes;
- stuck work: `rig parked`, blocked rows;
- cost rows.

## Output (one artifact)

One **ranked improvement list**. Each line: the finding, the size (ruling / tool edit / skill edit / doc fix /
drop), and the builder. Ranked by cost x frequency, the same rule as triage.

## Then

- The list goes to the lead, who turns each accepted line into a board task (`friction-triage` owns the open).
- Anything that is a governance change goes to the owner, not into the list (`autonomy-charter`).
- The owner digest is capped at the **top 3 decisions** and carries decisions only - no status, no narrative.

## Boundaries

- Two readers, one list. Do not produce a second report for the architect and a third for the lead.
- No new machinery: a review that needs a surface which does not exist has found its own first finding.
