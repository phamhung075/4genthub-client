# The guard judges the paths that make a directory entry

### Added
- `rust/agenthub-runtime/assets/seat-guard.ts`: `writeTargets` also collects the operands of the statements that MAKE or REMOVE a directory entry without writing a byte - `touch`, `mkdir`, `rmdir` - so the path each of them builds is read by the two rules that already read that list and by no new one. Measured before this change on the committed asset: `touch <seat dir>/config.yml` (the config the deny patterns are rendered into), `mkdir -p <seat dir>/hooks/pre` and `rmdir <seat dir>/hooks/pre` (the directory the guard is installed in), `touch <room>/limits.json` (the budget the breaker enforces), `touch <the shared checkout>/planted.go`, `mkdir -p /home/other/elsewhere` and `rmdir /home/other/empty` were all answered `allow`, while the byte-writing forms of the same paths (`echo x > ...`, `cp ...`) were refused the same day.
- The three protected paths that name a DIRECTORY - `scripts/git-hooks`, `.git/hooks`, `hooks/pre` - now match the directory itself and not only the files inside it. A trailing slash covered only the CONTENTS, and a seat's own directory and worktrees are inside `worktree-scope`, so `rm -rf <worktree>/scripts/git-hooks`, `mkdir -p <worktree>/.git/hooks` and `rmdir <seat dir>/hooks/pre` were judged by NO rule: the path that keeps the guard installed was the one path no rule saw.

### Testing
- `rust/agenthub-runtime/tests/seat_guard.rs`: `a_seat_cannot_touch_or_mkdir_a_path_no_rule_would_see` - four empty-path tamper cases that must report `protected-paths`, the two protected directories, and three out-of-scope cases that must report `worktree-scope` - and `an_ordinary_touch_or_mkdir_stays_the_seat_s_own` - a touch, a `mkdir -p` and an `rmdir` inside the worktree, `mkdir -p $VAR`, the temp dir, a file in the seat's own directory and a `hooks/preflight` segment all stay allowed, so the rule is a net and not a blanket ban on making directories.
- `cargo test --offline --test seat_guard` in `rust/agenthub-runtime`: 13 passed, 0 failed, and `cargo test --offline` for the crate: 133 + 13 + 1, 0 failed. Red first, against the committed asset: the new tamper case fails on its first command (`touch <seat dir>/config.yml` -> allowed) while the eleven cases that were already there pass.
- Out of tree, a probe that drives the file the way agy does (`node <seat-guard.ts> --agy-hook pre`, one case per call, the seat directory and the launcher's worktree list shaped like a real room's): 24 of 37 cases as expected on the committed asset and 37 of 37 with this one, the thirteen that moved being exactly the cases the base judged by no rule.

### Still unjudged, and named in the test's doc comment
- A path built by a program rather than by the shell: `python3 -c "open(P,'w')"`, `sh -c '...'`, an editor, `find -delete`, `xargs touch`, and a glob (`rm <seat dir>/*`). The guard judges the text of a command, so a command that only NAMES a path some other process writes is outside every rule here - what closes that is a check the seat cannot write, as the earlier entry in this family says.
