# A seat starts in the directory the room names for it, and the guard is handed that list

### Fixed
- `rust/agenthub-runtime/src/supervisor/mod.rs`: `start_seat` resolved the seat's directory as `seat.cwd` else `spec.cwd` else `.` - the DAEMON's own directory, the checkout every seat on this host shares - and exported it as `AGENTHUB_WORKTREE`, so a room that named no `cwd` gave each of its seats write scope over the shared checkout while the seat's own worktree stayed clean (the architect's finding, 2026-10-16: five omp pids rooted there, `agenthub-frontend/e2e/room-decision-panel.spec.ts` written into the shared checkout). The resolution is now `seat_scope`: the spec's directory for the seat FIRST (the pane's cwd, and what a relative path resolves against), then the seat's own worktrees under the room's `wt/` - `<seat>`, then `<seat>-<repo>` - and the whole list travels to the guard as `AGENTHUB_WORKTREES`. A seat the room names no directory for, in a room that holds no worktree for it, is REFUSED with the reason and both ways to give it one; a relative `cwd` is refused too, because it would resolve against the daemon's own directory.
- `rust/agenthub-runtime/src/runner/mod.rs`: the runner resolved the seat's directory a second time with the same `.` default, so an agent could be spawned in the shared checkout even when its pane was elsewhere. It now asks `seat_scope`, and both launch refusals (the policy config and the seat's directory) leave through one path, so a seat that never came up has one place to read why.

### Parked for the owner (the guard's own source is the owner's to change)
- `PARKED-seat-cwd-scope-guard.patch` (in the go-dev seat directory): `seat-guard.ts` takes the list from `AGENTHUB_WORKTREES` instead of deriving it, drops `ownWorktree`, and FAILS CLOSED - the version this replaces answered `return ""` when the variable was absent, which allowed every write, the shared checkout included. Apply it with the launcher change, in the same client main, before the next reseat: the new guard reads `AGENTHUB_WORKTREES`, which only the new launcher sets.

### Testing

### Note for the room
- Every seat now needs a directory of its own: `cwd` for it in `team.json`/`spec.json`, or a worktree at `<roomDir>/wt/<seat>`.
