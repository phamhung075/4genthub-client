# A seat does not raise the ceiling that bounds it

### Changed
- `internal/clientroom/limits.go`: `4genteam room limits` refuses a raise asked for by a SEAT. Measured on the real binary before this rule (a throwaway state dir, the caller a seat): `--usd 999` wrote 999 into the file and `--off` disabled the ceilings, so the seat a ceiling exists to stop was the one who could lift it. The refusal names the marker and the way out - a seat may LOWER a ceiling or turn the ceilings ON; the OWNER raises one, running the verb with $AGENTHUB_SESSION_NAME unset. `--off` is a raise only while the ceilings are ON, and a number the file does not carry yet is not a ceiling, so writing that one raises nothing: a room with no file can still be given its agreed 25/300 by whoever runs it.
- `internal/clientroom/limits.go`, `internal/clientroom/room.go`, `internal/roombudget/roombudget.go`: the strings I landed at 6b4db16 measured the guard BEFORE the park-semantics lane merged, and they are stale at main. The merged guard NAMES the room's `limits.json` and the seat's `parked.json` in its protected paths, and its write-target parsing now covers `rm`/`unlink`/`truncate`/`shred`, `sed -i`/`perl -i` and `dd of=` as well as an edit tool's path, a redirect, `tee` and cp/mv/install/rsync/ln. Measured at bf43cce by driving the guard: every one of those is REFUSED on both files, so the "an edit tool and a redirect are refused; sed -i, rm, truncate, dd of= pass" sentence is wrong at main and is replaced by what the guard refuses. What still passes, in the same run, is a path opened from INSIDE a program (`python3 -c "open(...)"`, `node -e "writeFileSync(...)"`) or spelled through a variable: neither layer sees it, and the three strings say so instead.

It asserts the OWNER's writes (25 -> 40 is a raise) and inherited the caller's identity from the shell before this change, so it passed in a bare shell and failed in a seat's - the same non-hermetic shape the clientroom queue case had.
