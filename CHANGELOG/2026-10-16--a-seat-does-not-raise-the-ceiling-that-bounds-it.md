# A seat does not raise the ceiling that bounds it

### Changed
- `internal/clientroom/limits.go`: `4genteam room limits` refuses a raise asked for by a SEAT. Measured on the real binary before this rule (a throwaway state dir, the caller a seat): `--usd 999` wrote 999 into the file and `--off` disabled the ceilings, so the seat a ceiling exists to stop was the one who could lift it. The refusal names the marker and the way out - a seat may LOWER a ceiling or turn the ceilings ON; the OWNER raises one, running the verb with $AGENTHUB_SESSION_NAME unset. `--off` is a raise only while the ceilings are ON, and a number the file does not carry yet is not a ceiling, so writing that one raises nothing: a room with no file can still be given its agreed 25/300 by whoever runs it.
- `internal/clientroom/limits.go`, `internal/clientroom/room.go`: the package doc and both usage texts state the rule and keep what is still OPEN apart from it. The marker is a SPEED BUMP, not a wall - $AGENTHUB_SESSION_NAME is a seat's identity for the rail and the git hooks, and a seat that unsets it claims to be the owner - and the FILE shapes the seat guard does not parse (`sed -i`, `rm`, `truncate`, `dd of=`, any program) still pass until the parked destructive-write patch lands. This closes the VERB route, not the file.

### Testing
- `internal/clientroom/limits_test.go`: `TestASeatDoesNotRaiseTheCeilingThatBoundsIt` - five raises refused (`--usd 999`, `--usd 25.01`, `--calls 301`, `--off`, and a pair at once), each naming the marker and the OWNER, printing nothing and leaving the file unchanged, then three tightenings allowed (a lower USD ceiling, a lower call ceiling, `--on`). Red first on the binary before the rule, measured: `[--usd 999] exited 0, want 3`, `[--usd 999] left {Enabled:true USDPerSeat24h:999 CallsPerSeatMin:300}, want the ceilings unchanged at {Enabled:true USDPerSeat24h:25 CallsPerSeatMin:300}`, `[--off] exited 0, want 3`.
- `internal/clientroom/limits_test.go`: `TestTheOwnerRaisesTheCeilingAndAnAlreadyOffCeilingIsNotARaise` - with the variable unset (the owner's own shell, where the owner runs it) the raise is written, and a seat asking `--off` for a room that is already OFF passes, because nothing in force is lost. The suite cannot drive the unset case through a seat's shell (the seat guard refuses `env -u AGENTHUB_SESSION_NAME` as a hook bypass, measured), so the case is pinned with `t.Setenv` and the real-binary run covers the seat half.
- `internal/clientroom/limits_test.go`: `TestRoomLimitsWritesKeepsAndTurnsOff` now pins $AGENTHUB_SESSION_NAME empty. It asserts the OWNER's writes (25 -> 40 is a raise) and inherited the caller's identity from the shell before this change, so it passed in a bare shell and failed in a seat's - the same non-hermetic shape the clientroom queue case had.
