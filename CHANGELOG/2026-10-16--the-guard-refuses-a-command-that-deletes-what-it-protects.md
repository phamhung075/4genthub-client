# The guard refuses a command that deletes or rewrites what it protects

### Added
- `rust/agenthub-runtime/assets/seat-guard.ts`: `writeTargets` now collects the operands of the statements that DELETE a file or rewrite it in place - `rm`, `unlink`, `truncate`, `shred`, `sed -i`/`perl -i`, `dd of=` - and EVERY operand of an `mv`, whose source the move removes, not only the target of a redirect, a `tee` or a `cp`. `protected-paths` and `worktree-scope` both read that list, so these forms are judged by the rule the same file was already subject to. Measured before this change, with the guard exactly as it landed earlier the same day: `rm <seat dir>/config.yml`, `rm <seat dir>/hooks/pre/seat-guard.ts`, `sed -i s/x/y/ <seat dir>/tool-calls.jsonl`, `truncate -s0 <seat dir>/parked.json` and `dd of=<seat dir>/parked.json` were judged by NO rule, while the edit-shaped form of the same write was refused. The protection added that day was therefore bypassable by one command, one character longer than the one it refused.
- The park record and the room's budget join the protected set: `<seat dir>/parked.json`, the breaker's record that the seat is stopped, and the room's `limits.json` two levels up, the budget the breaker enforces. Both are named by DIRECTORY and not by file name, so a project file that happens to be called `parked.json` or `limits.json` stays the seat's to edit.

### Testing
- `rust/agenthub-runtime/tests/seat_guard.rs`: `a_seat_cannot_delete_or_rewrite_the_files_the_rules_rest_on` - nine commands and two write-tool targets, each of which must report `protected-paths` - and `an_ordinary_deletion_still_stays_the_seat_s_own` - a worktree path, the temp dir, a target it cannot judge (`$VAR`), an in-place edit inside the worktree and a `dd` inside it all stay allowed, so the rule is a net and not a blanket ban on deleting.
- `cargo test --offline --test seat_guard` in `rust/agenthub-runtime`: 9 passed, 0 failed. With the previous `seat-guard.ts` the two new cases fail (the first on `rm <seat dir>/config.yml`, allowed).
- Out of tree, a probe that drives the file the way agy does (`node seat-guard.ts --agy-hook pre`, one case per call) measures 9 of 16 cases as expected on the previous file and 16 of 16 with this one.

### Still unjudged, and named in the test's doc comment
- A glob (`rm <seat dir>/*`), `find -delete`, `xargs rm`, and any write a script makes that the command only names - `python3 -c "open(P,'w')"`, `sh -c '...'`, an editor. The guard sees the command text, not what a script does with its arguments, so a seat that means to is not stopped by this rule alone: what closes that is a check the seat cannot write, not a longer regex.
